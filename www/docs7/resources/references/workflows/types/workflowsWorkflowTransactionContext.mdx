title: WorkflowTransactionContext
---

- `WorkflowTransactionContext`: [StepExecutionContext](/resources/references/workflows/interfaces/workflowsStepExecutionContext) & [TransactionContext](/resources/references/workflows/classes/workflowsTransactionContext) & `object`
  - `workflowId`: `string` — The ID of the workflow.
  - `attempt`: `number` — The attempt number of the step.
  - `idempotencyKey`: `string` — The idempoency key of the step.
  - `parentStepIdempotencyKey`: `string` (optional) — The idempoency key of the parent step.
  - `preventReleaseEvents`: `boolean` (optional) — Whether to prevent release events.
  - `stepName`: `string` — The name of the step.
  - `action`: `"invoke"` | `"compensate"` — The action of the step.
  - `container`: [MedusaContainer](/resources/references/workflows/types/workflowsMedusaContainer) — The container used to access resources, such as services, in the step.
  - `metadata`: [TransactionMetadata](/resources/references/workflows/types/workflowsTransactionMetadata) — Metadata passed in the input.
    - `model_id`: `string`
    - `idempotency_key`: `string`
    - `action`: `string`
    - `action_type`: [TransactionHandlerType](/resources/references/workflows/enums/workflowsTransactionHandlerType)
    - `attempt`: `number`
    - `timestamp`: `number`
  - `context`: [Context](/resources/references/workflows/interfaces/workflowsContext) — A context used to share resources, such as transaction manager, between the application and the module.
    - `transactionManager`: TManager (optional) — An instance of a transaction manager of type `TManager`, which is a typed parameter passed to the context to specify the type of the `transactionManager`.
    - `manager`: TManager (optional) — An instance of a manager, typically an entity manager, of type `TManager`, which is a typed parameter passed to the context to specify the type of the `manager`.
    - `isolationLevel`: `string` (optional) — A string indicating the isolation level of the context. Possible values are `READ UNCOMMITTED`, `READ COMMITTED`, `REPEATABLE READ`, or `SERIALIZABLE`.
    - `enableNestedTransactions`: `boolean` (optional) — A boolean value indicating whether nested transactions are enabled.
    - `eventGroupId`: `string` (optional) — A string indicating the ID of the group to aggregate the events to be emitted at a later point.
    - `transactionId`: `string` (optional) — A string indicating the ID of the current transaction.
    - `runId`: `string` (optional) — A string indicating the ID of the current run.
    - `messageAggregator`: [IMessageAggregator](/resources/references/workflows/interfaces/workflowsIMessageAggregator) (optional) — An instance of a message aggregator, which is used to aggregate messages to be emitted at a later point.
    - `requestId`: `string` (optional) — A string indicating the ID of the current request.
    - `idempotencyKey`: `string` (optional) — A string indicating the idempotencyKey of the current workflow execution.
    - `parentStepIdempotencyKey`: `string` (optional) — A string indicating the idempotencyKey of the parent workflow execution.
    - `preventReleaseEvents`: `boolean` (optional) — preventReleaseEvents
    - `isCancelling`: `boolean` (optional) — A boolean value indicating whether the current workflow execution is being cancelled.
    - `cancelingFromParentStep`: `boolean` (optional) — Weither or not a sub workflow cancellation is being triggered from a parent step. If true, the parent step will not be triggered by the sub workflow.
  - `eventGroupId`: `string` (optional) — A string indicating the ID of the group to aggregate the events to be emitted at a later point.
  - `transactionId`: `string` (optional) — A string indicating the ID of the current transaction.
  - `runId`: `string` (optional) — A string indicating the ID of the current run.
  - ` stepDefinition`: [TransactionStepsDefinition](/resources/references/workflows/types/workflowsTransactionStepsDefinition) — Get access to the definition of the step.
    - `uuid`: `string` (optional) — A unique identifier for the transaction step. This is set automatically when declaring a workflow with "createWorkflow"
    - `action`: `string` (optional) — Specifies the action to be performed in this step. "name" is an alias for action when creating a workflow with "createWorkflow".
    - `continueOnPermanentFailure`: `boolean` (optional) — Indicates whether the workflow should continue even if there is a permanent failure in this step. In case it is set to true, the current step will be marked as TransactionStepState.PERMANENT\_FAILURE and the next steps will be executed.
    - `skipOnPermanentFailure`: `boolean` | `string` (optional) — Indicates whether the workflow should skip all subsequent steps in case of a permanent failure in this step. In case it is set to true, the next steps of the workflow will not be executed and their status will be marked as TransactionStepState.SKIPPED\_FAILURE. In case it is a string, the next steps until the step name provided will be skipped and the workflow will be resumed from the step provided.
    - `noCompensation`: `boolean` (optional) — If true, no compensation action will be triggered for this step in case of a failure.
    - `maxRetries`: `number` (optional) — The maximum number of times this step should be retried in case of temporary failures. The default is 0 (no retries).
    - `autoRetry`: `boolean` (optional) — If true, the step will be retried automatically in case of a temporary failure. The default is true.
    - `retryInterval`: `number` (optional) — The interval (in seconds) between retry attempts after a temporary failure. The default is to retry immediately.
    - `retryIntervalAwaiting`: `number` (optional) — The interval (in seconds) to retry a step even if its status is "TransactionStepStatus.WAITING".
    - `maxAwaitingRetries`: `number` (optional) — The maximum number of times to retry a step even if its status is "TransactionStepStatus.WAITING".
    - `timeout`: `number` (optional) — The maximum amount of time (in seconds) to wait for this step to complete. This is NOT an execution timeout, the step will always be executed and wait for its response. If the response is not received within the timeout set, it will be marked as "TransactionStepStatus.TIMEOUT" and the workflow will be reverted as soon as it receives the response.
    - `async`: `boolean` (optional) — If true, the step is executed asynchronously. This means that the workflow will not wait for the response of this step. Async steps require to have their responses set using "setStepSuccess" or "setStepFailure", unless it is combined with "backgroundExecution: true". If combined with a timeout, and any response is not set within that interval, the step will be marked as "TransactionStepStatus.TIMEOUT" and the workflow will be reverted immediately.
    - `nested`: `boolean` (optional) — It flags where the step contains a sub transaction inside itself.
    - `backgroundExecution`: `boolean` (optional) — It applies to "async" steps only, allowing them to run in the background and automatically complete without external intervention. It is ideal for time-consuming tasks that will be complete after the execution, contrasting with standard "async" operations that require a response to be set in a later stage.
    - `compensateAsync`: `boolean` (optional) — If true, the compensation function for this step is executed asynchronously. Which means, the response has to be set using "setStepSuccess" or "setStepFailure".
    - `noWait`: `boolean` (optional) — If true, the workflow will not wait for their sibling steps to complete before moving to the next step.
    - `saveResponse`: `boolean` (optional) — If true, the response of this step will be stored. Default is true.
    - `next`: [TransactionStepsDefinition](/resources/references/workflows/types/workflowsTransactionStepsDefinition) | [TransactionStepsDefinition](/resources/references/workflows/types/workflowsTransactionStepsDefinition)\[] (optional) — Defines the next step(s) to execute after this step. Can be a single step or an array of steps.
    - `store`: `boolean` (optional) — Whether we need to store checkpoint at this step.
  - `payload`: `unknown` — Object containing the initial payload.
  - `invoke`: `Record<string, unknown>` — Object containing responses of Invoke handlers on steps flagged with saveResponse.
  - `compensate`: `Record<string, unknown>` — Object containing responses of Compensate handlers on steps flagged with saveResponse.
  - `invoke`: `object`
