## Returns

**getOptions**

- `timeout`: `number` (optional) — The global timeout for the entire transaction workflow (in seconds).
- `store`: `boolean` (optional) — If true, the state of the transaction will be persisted. Learn more in [this documentation](/learn/fundamentals/workflows/store-executions).
- `retentionTime`: `number` (optional) — The number of seconds that the workflow execution should be stored in the database. Learn more in [this documentation](/learn/fundamentals/workflows/store-executions).
- `storeExecution`: `boolean` (optional, deprecated) — If true, the execution details of each step will be stored.

  Deprecated: no longer needed.
- `idempotent`: `boolean` (optional) — If true, the workflow will use the transaction ID as the key to ensure only-once execution
- `schedule`: `string` | [SchedulerOptions](/resources/references/workflows/types/workflowsSchedulerOptions) (optional) — Defines the workflow as a scheduled workflow that executes based on the cron configuration passed. The value can either by a cron expression string, or an object that also allows to define the concurrency behavior.
