---
title: batchVariantImages
---

This method manages variant-image associations for a specific variant. It sends a request to the
[Batch Variant Images](/api/admin/products/manage-images-of-product-variant)
API route.

> **Note**
>
> This is available starting from [Medusa v2.11.2](https://github.com/medusajs/medusa/releases/tag/v2.11.2).

## Example

```ts
sdk.admin.product.batchVariantImages("prod_123", "variant_123", {
  add: ["img_123", "img_456"],
  remove: ["img_789"]
})
.then(({ added, removed }) => {
  console.log(added, removed)
})
```

<a id="batchvariantimages-parameters" />

## Parameters

**batchVariantImages**

- `productId`: `string` — The product's ID.
- `variantId`: `string` — The variant's ID.
- `body`: [AdminBatchVariantImagesRequest](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminBatchVariantImagesRequest) — The images to add or remove from the variant.
  - `add`: `string`\[] (optional) — The image IDs to add to the variant.
  - `remove`: `string`\[] (optional) — The image IDs to remove from the variant.
- `headers`: [ClientHeaders](/resources/references/js_sdk/admin/types/js_sdkadminClientHeaders) (optional) — Headers to pass in the request
  - `tags`: `string`\[] — Tags to cache data under for Next.js applications. Learn more in [Next.js's documentation](https://nextjs.org/docs/app/building-your-application/caching#fetch-optionsnexttags-and-revalidatetag).

<a id="batchvariantimages-returns" />

## Returns

**batchVariantImages**

- `Promise`: Promise\<[AdminBatchVariantImagesResponse](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminBatchVariantImagesResponse)> — The batch operation details.
  - `added`: `string`\[] — The image IDs that were added to the variant.
  - `removed`: `string`\[] — The image IDs that were removed from the variant.
