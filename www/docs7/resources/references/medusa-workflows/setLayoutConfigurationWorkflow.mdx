This documentation provides a reference to the `setLayoutConfigurationWorkflow`. It belongs to the `@medusajs/medusa/core-flows` package.

This workflow sets a layout configuration for a zone, either as the user's
personal configuration or as the system default. It also persists the saved
scope as the user's active view for the zone, so it sticks across reloads.

This workflow is used by the
[Set Layout Configuration Admin API Route](/api/admin/layouts/add-layout-configuration).

You can use this workflow within your own customizations or custom workflows,
allowing you to set a layout configuration within your custom flows.

> **Note**
>
> This is available starting from [Medusa v2.17.2](https://github.com/medusajs/medusa/releases/tag/v2.17.2).

[View source code](https://github.com/medusajs/medusa/blob/0ed927bdb7a396a8fd5f6447ed69b7b354b150d3/packages/core/core-flows/src/settings/workflows/set-layout-configuration.ts#L66)

## Examples

**API Route**

```ts title="src/api/workflow/route.ts"
import type {
  MedusaRequest,
  MedusaResponse,
} from "@medusajs/framework/http"
import { setLayoutConfigurationWorkflow } from "@medusajs/medusa/core-flows"

export async function POST(
  req: MedusaRequest,
  res: MedusaResponse
) {
  const { result } = await setLayoutConfigurationWorkflow(req.scope)
    .run({
      input: {
        zone: "products",
        user_id: "user_123",
        configuration: {
          // ...
        },
      },
    })

  res.send(result)
}
```

## Steps

- [setLayoutConfigurationStep](/resources/references/medusa-workflows/steps/setLayoutConfigurationStep): This step sets a layout configuration for a zone, either as the user's personal configuration or as the system default.
  - [setActiveLayoutScopeStep](/resources/references/medusa-workflows/steps/setActiveLayoutScopeStep): This step sets a user's active layout scope for a zone, which determines whether the user's personal or the system default configuration is shown.

<a id="setlayoutconfigurationworkflow-input" />

## Input

**setLayoutConfigurationWorkflow**

- `SetLayoutConfigurationWorkflowInput`: [SetLayoutConfigurationWorkflowInput](/resources/references/core_flows/core_core_flows_src/types/core_flowscore_core_flows_srcSetLayoutConfigurationWorkflowInput)
  - `zone`: `string` — The zone that the layout configuration applies to.
  - `user_id`: `string` — The ID of the user that the layout configuration belongs to.
  - `is_default`: `boolean` (optional) — Whether to set the configuration as the system default for the zone, rather than the user's personal configuration.
  - `configuration`: [LayoutConfigurationData](/resources/references/settings/interfaces/settingsLayoutConfigurationData) — The layout configuration data to set.
    - `widgets`: `Record<string, [LayoutWidgetPreference](/references/settings/interfaces/settings.LayoutWidgetPreference)>` — Per-widget placement and visibility preferences, keyed by widget ID.
      - `hidden`: `boolean` (optional) — Whether the widget is hidden.
      - `section`: `string` (optional) — Override which section this widget appears in.
      - `order`: `number` (optional) — Override the sort order of the widget within its section.

<a id="setlayoutconfigurationworkflow-output" />

## Output

**setLayoutConfigurationWorkflow**

- `LayoutConfigurationDTO`: [LayoutConfigurationDTO](/resources/references/settings/interfaces/settingsLayoutConfigurationDTO) — The layout configuration data model. Unlike view configurations, there is at most one layout configuration per `(zone, user_id)` pair, plus an optional single system default per zone.
  - `id`: `string` — The ID of the configuration.
  - `zone`: `string` — The zone (page) this configuration is for, e.g. "product.details".
  - `user_id`: `null` | `string` — The user ID this configuration belongs to, or null for the system default.
  - `is_system_default`: `boolean` — Whether this is the system default configuration for the zone.
  - `configuration`: [LayoutConfigurationData](/resources/references/settings/interfaces/settingsLayoutConfigurationData) — The layout configuration data.
    - `widgets`: `Record<string, [LayoutWidgetPreference](/references/settings/interfaces/settings.LayoutWidgetPreference)>` — Per-widget placement and visibility preferences, keyed by widget ID.
      - `hidden`: `boolean` (optional) — Whether the widget is hidden.
      - `section`: `string` (optional) — Override which section this widget appears in.
      - `order`: `number` (optional) — Override the sort order of the widget within its section.
  - `created_at`: `Date` — The date the configuration was created.
  - `updated_at`: `Date` — The date the configuration was last updated.
