This documentation provides a reference to the `createPasswordResetTokenStep`. It belongs to the `@medusajs/medusa/core-flows` package.

Issues a single-use password reset token via the auth module. The token's
`jti` is meant to be embedded in the JWT delivered to the user; the auth
module stores its hash in a dedicated table so the consume side can verify
and atomically delete it on first use.

Issuing a new token automatically invalidates any prior password-reset
tokens for the same provider identity. Compensation consumes the token
(best-effort) if the workflow rolls back.

> **Note**
>
> This is available starting from [Medusa v2.16.0](https://github.com/medusajs/medusa/releases/tag/v2.16.0).

```ts title="src/workflows/my-workflow.ts"
import { createWorkflow } from "@medusajs/framework/workflows-sdk"
import { createPasswordResetTokenStep } from "@medusajs/medusa/core-flows"

const myWorkflow = createWorkflow(
  "my-workflow",
  () => {
    const data = createPasswordResetTokenStep({
      "entityId": "{value}",
      "provider": "{value}",
      "ttlSeconds": 6
    })
  }
)
```

<a id="createpasswordresettokenstep-input" />

## Input

**createPasswordResetTokenStep**

- `CreatePasswordResetTokenStepInput`: [CreatePasswordResetTokenStepInput](/resources/references/core_flows/core_core_flows_src/types/core_flowscore_core_flows_srcCreatePasswordResetTokenStepInput)
  - `entityId`: `string` — The entity ID for which to create the password reset token.
  - `provider`: `string` — The auth provider name.
  - `ttlSeconds`: `number` — Time-to-live for the token in seconds.

<a id="createpasswordresettokenstep-output" />

## Output

**createPasswordResetTokenStep**

- `CreatePasswordResetTokenStepOutput`: [CreatePasswordResetTokenStepOutput](/resources/references/core_flows/core_core_flows_src/types/core_flowscore_core_flows_srcCreatePasswordResetTokenStepOutput)
  - `jti`: `string` — The JWT ID (JTI) for the password reset token.
  - `expiresAt`: `string` — The expiration date and time of the token in ISO format.
