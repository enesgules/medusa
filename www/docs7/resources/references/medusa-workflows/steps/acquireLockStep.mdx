This documentation provides a reference to the `acquireLockStep`. It belongs to the `@medusajs/medusa/core-flows` package.

This step acquires a lock for a given key. Learn more about locks in the [Locking Module](/resources/infrastructure-modules/locking)
guide.

## Example

```ts
const data = acquireLockStep({
  "key": "my-lock-key",
  "ttl": 60
})
```

<a id="acquirelockstep-input" />

## Input

**acquireLockStep**

- `AcquireLockStepInput`: [AcquireLockStepInput](/resources/references/core_flows/core_core_flows_src/interfaces/core_flowscore_core_flows_srcAcquireLockStepInput)
  - `key`: `string` | `string`\[] — The keys to be locked
  - `timeout`: `number` (optional, default: 0) — The maximum time (in seconds) to wait for acquiring the lock. If the lock cannot be acquired within this time, an error is thrown.
  - `retryInterval`: `number` (optional, default: 0.3) — The time (in seconds) to wait between each retry to acquire the lock.
  - `ttl`: `number` (optional) — The expiration time (in seconds) for the lock. If the lock is already acquired and the owner is the same, the expiration time is extended by the value passed. If not specified, the lock does not expire.
  - `ownerId`: `string` (optional) — The owner ID for the lock. If specified, only the owner can release the lock or extend its expiration time.
  - `provider`: `string` (optional) — The provider name to use for locking. If no provider is passed, the default provider (in-memory or the provider configured in medusa-config.ts) will be used.
  - `executeOnSubWorkflow`: `boolean` (optional)
