This documentation provides a reference to the `sdk.auth.callback` method used to send requests to Medusa's Authentication API routes. It can be used for admin users, customers, or custom actor types.

This method is used to validate an Oauth callback from a third-party service, such as Google, for an admin user, customer, or custom actor types.
It sends a request to the [Validate Authentication Callback](/api/admin/auth/validate-authentication-callback).

The method stores the returned token and passes it in the header of subsequent requests. So, you can call the
[store.customer.create](/resources/references/js-sdk/store/customer#create) or [refresh](/resources/references/js-sdk/auth/refresh) methods,
for example, after calling this method.

Learn more in the [JS SDK Authentication](/resources/js-sdk/auth/overview) guide.

## Example

```ts
await sdk.auth.callback(
  "customer",
  "google",
  {
    code: "123",
    state: "456"
  }
)

// all subsequent requests will use the token in the header
const { customer } = await sdk.store.customer.create({
  email: "customer@gmail.com",
  password: "supersecret"
})
```

<a id="callback-parameters" />

## Parameters

**callback**

- `actor`: `string` — The actor type. For example, `user` for admin user, or `customer`.
- `method`: `string` — The authentication provider to use. For example, `google`.
- `query`: `Record<string, unknown>` (optional) — The query parameters from the Oauth callback, which should be passed to the API route. This includes query parameters like `code` and `state`.

<a id="callback-returns" />

## Returns

**callback**

- `Promise`: Promise\<[AuthCallbackResponse](/resources/references/js_sdk/auth/types/js_sdkauthAuthCallbackResponse)> — The authentication JWT token
  - `token`: `string` — A token without an actor type (permissions) attached to it. Used to request and confirm verifications.
  - `mfa_required`: `true` — Indicates that the client must complete the returned MFA challenge.
  - `mfa_challenge`: [AuthMfaChallengeDTO](/resources/references/auth/types/authAuthMfaChallengeDTO) — The MFA challenge to complete.
    - `id`: `string` — The multi-factor authentication (MFA) challenge's ID.
    - `auth_identity_id`: `string` (optional) — The ID of the authentication identity being challenged.
    - `auth_identity`: [AuthIdentityDTO](/resources/references/auth/interfaces/authAuthIdentityDTO) (optional) — The authentication identity being challenged.
    - `auth_provider`: `string` | `null` (optional) — The authentication provider handling the challenge.
    - `methods`: [AuthMfaChallengeMethod](/resources/references/auth/types/authAuthMfaChallengeMethod)\[] — Available methods for completing this challenge.
    - `expires_at`: `Date` — When the challenge expires.
    - `attempts`: `number` — Number of verification attempts made.
    - `max_attempts`: `number` — Maximum verification attempts allowed.
    - `completed_at`: `Date` | `null` (optional) — When the challenge was completed.
    - `metadata`: `Record<string, unknown>` | `null` (optional) — Additional metadata for the challenge.
  - `verification_required`: `true` — Indicates that the client must complete verification.
  - `verification`: [AuthVerificationDTO](/resources/references/auth/types/authAuthVerificationDTO) (optional) — The verification state to show to the caller.
    - `id`: `string` (optional)
    - `entity_id`: `string`
    - `auth_identity_id`: `string`
    - `entity_type`: `string`
    - `code_provider`: `string`
    - `provider_metadata`: `Record<string, unknown>` | `null` (optional)
    - `metadata`: `Record<string, unknown>` | `null` (optional)
    - `verified_at`: `Date` | `null` (optional)
    - `requested_at`: `Date`
