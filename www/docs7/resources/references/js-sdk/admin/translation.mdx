This documentation provides a reference to the `sdk.admin.translation` set of methods used to send requests to Medusa's Admin API routes.

## list

This method retrieves a paginated list of translations. It sends a request to the
[List Translations](/api/admin/translations/list-translations)
API route.

### Example

To retrieve the list of translations:

```ts
sdk.admin.translation.list()
.then(({ translations, count, limit, offset }) => {
  console.log(translations)
})
```

To configure the pagination, pass the `limit` and `offset` query parameters.

For example, to retrieve only 10 items and skip 10 items:

```ts
sdk.admin.translation.list({
  limit: 10,
  offset: 10
})
.then(({ translations, count, limit, offset }) => {
  console.log(translations)
})
```

Using the `fields` query parameter, you can specify the fields and relations to retrieve
in each translation:

```ts
sdk.admin.translation.list({
  fields: "id,name"
})
.then(({ translations, count, limit, offset }) => {
  console.log(translations)
})
```

Learn more about the `fields` property in the [API reference](/api/store/select-fields-and-relations).

## batch

This method allows bulk operations on translations. It sends a request to the
[Manage Translations](/api/admin/translations/manage-translations)
API route.

### Example

```ts
sdk.admin.translation.batch({
  create: [
    {
      reference_id: "prod_123",
      reference: "product",
      locale_code: "en-US",
      translations: { title: "Shirt" }
    }
  ],
  update: [
    {
      id: "trans_123",
      translations: { title: "Pants" }
    }
  ],
  delete: ["trans_321"]
})
.then(({ created, updated, deleted }) => {
  console.log(created, updated, deleted)
})
```

<a id="batch-parameters" />

### Parameters

**batch**

- `body`: [AdminBatchTranslations](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminBatchTranslations)
  - `create`: [AdminCreateTranslation](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminCreateTranslation)\[] (optional) — The translations to create.
    - `reference_id`: `string` — The ID of the entity being translated.
    - `reference`: `string` — The type of entity being translated (e.g., "product", "product\_variant").
    - `locale_code`: `string` — The BCP 47 language tag code for this translation (e.g., "en-US", "fr-FR").
    - `translations`: `Record<string, string>` — The translated fields as key-value pairs.
  - `update`: [AdminUpdateTranslation](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminUpdateTranslation)\[] (optional) — The translations to update.
    - `id`: `string` — The ID of the translation.
    - `reference_id`: `string` (optional) — The ID of the entity being translated.
    - `reference`: `string` (optional) — The type of entity being translated.
    - `locale_code`: `string` (optional) — The BCP 47 language tag code for this translation.
    - `translations`: `Record<string, string>` (optional) — The translated fields as key-value pairs.
  - `delete`: `string`\[] (optional) — The translations to delete.
- `headers`: [ClientHeaders](/resources/references/js_sdk/admin/types/js_sdkadminClientHeaders) (optional) — Headers to pass in the request.
  - `tags`: `string`\[] — Tags to cache data under for Next.js applications. Learn more in [Next.js's documentation](https://nextjs.org/docs/app/building-your-application/caching#fetch-optionsnexttags-and-revalidatetag).

## settings

This method retrieves the settings for the translations for a given entity type or all entity types if no entity type is provided.
It sends a request to the
[Get Translation Settings](/api/admin/translations/list-settings) API route.

### Example

To retrieve the settings for the translations for a given entity type:

```ts
sdk.admin.translation.settings({
  entity_type: "product"
})
.then(({ translation_settings }) => {
  console.log(translation_settings)
})
```

To retrieve the settings for all entity types:

```ts
sdk.admin.translation.settings()
.then(({ translation_settings }) => {
  console.log(translation_settings)
})
```

To retrieve the settings for active entities only:

```ts
sdk.admin.translation.settings({
  is_active: true
})
.then(({ translation_settings }) => {
  console.log(translation_settings)
})
```

To retrieve the settings for inactive entities only:

```ts
sdk.admin.translation.settings({
  is_active: false
})
.then(({ translation_settings }) => {
  console.log(translation_settings)
})
```

<a id="settings-parameters" />

### Parameters

**settings**

- `query`: [AdminTranslationSettingsParams](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminTranslationSettingsParams) (optional) — The query parameters which can optionally include the entity type to get the settings for and whether to get the settings for active/inactive entities only.
  - `entity_type`: `string` (optional) — The entity type to get the settings for (e.g., "product").
  - `is_active`: `boolean` (optional) — Whether to get the settings for active/inactive entities only.
- `headers`: [ClientHeaders](/resources/references/js_sdk/admin/types/js_sdkadminClientHeaders) (optional) — Headers to pass in the request.
  - `tags`: `string`\[] — Tags to cache data under for Next.js applications. Learn more in [Next.js's documentation](https://nextjs.org/docs/app/building-your-application/caching#fetch-optionsnexttags-and-revalidatetag).

<a id="settings-returns" />

### Returns

**settings**

- `Promise`: Promise\<[AdminTranslationSettingsResponse](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminTranslationSettingsResponse)> — The translation settings.
  - `translation_settings`: `Record<string, Pick<[AdminTranslationSettings](/references/types/HttpTypes/interfaces/types.HttpTypes.AdminTranslationSettings), "id" \| "fields" \| "is_active"> & object>` — A mapping of entity types to their tranlsation settings.

    ```
    { * "product": { * "id": "trset_123", * "fields": ["title", "description", "subtitle", "status"], * "is_active": true, * "inactive_fields": [] * }, * "product_variant": { * "id": "trset_456", * "fields": ["title", "material"], * "is_active": false, * "inactive_fields": [] * } * }
    ```

## batchSettings

[Batch Translation Settings](/api/admin/translations/manage-translation-settings)
API route.

> **Note**
>
> This is available starting from [Medusa v2.12.6](https://github.com/medusajs/medusa/releases/tag/v2.12.6).

```ts
sdk.admin.translation.batchSettings({
  create: [
    {
      entity_type: "product",
      fields: ["title", "description"],
      is_active: true

  update: [

      id: "trset_123",
      fields: ["title", "description", "subtitle"],
```

## entities

This method retrieves a paginated list of entities for a given entity type with only their
translatable fields.
It sends a request to the
[Get Translation Entities](/api/admin/translations/list-translatable-entities) API route.

> **Note**
>
> This is available starting from [Medusa v2.12.4](https://github.com/medusajs/medusa/releases/tag/v2.12.4).

### Example

To retrieve the entities for a given entity type:

```ts
sdk.admin.translation.entities({
  type: "product"
})
.then(({ data, count, offset, limit }) => {
  console.log(data)
})
```

To configure the pagination, pass the `limit` and `offset` query parameters.

For example, to retrieve only 10 items and skip 10 items:

```ts
sdk.admin.translation.entities({
  type: "product",
  limit: 10,
  offset: 10
})
.then(({ data, count, offset, limit }) => {
  console.log(data)
})
```
