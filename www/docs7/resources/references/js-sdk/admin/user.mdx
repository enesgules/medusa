This documentation provides a reference to the `sdk.admin.user` set of methods used to send requests to Medusa's Admin API routes.

## update

This method updates a user. It sends a request to the
[Update User](/api/admin/users/update-a-user)
API route.

### Example

```ts
sdk.admin.user.update("user_123", {
  first_name: "John",
  last_name: "Doe",
})
.then(({ user }) => {
  console.log(user)
})
```

<a id="update-parameters" />

### Parameters

**update**

- `id`: `string` — The ID of the user to update.
- `body`: [AdminUpdateUser](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminUpdateUser) — The details of the user to update.
  - `first_name`: `null` | `string` (optional) — The first name of the user.
  - `last_name`: `null` | `string` (optional) — The last name of the user.
  - `avatar_url`: `null` | `string` (optional) — The URL of the user's avatar image.
  - `metadata`: `null` | `Record<string, unknown>` (optional) — Custom key-value pairs that can be added to the user.
- `query`: [AdminUserParams](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminUserParams) (optional) — Configure the fields and relations to retrieve in the tax region.
  - `fields`: `string` (optional) — The fields and relations to retrieve separated by commas. Learn more in the [API reference](/api/store/select-fields-and-relations).
- `headers`: [ClientHeaders](/resources/references/js_sdk/admin/types/js_sdkadminClientHeaders) (optional) — Headers to pass in the request.
  - `tags`: `string`\[] — Tags to cache data under for Next.js applications. Learn more in [Next.js's documentation](https://nextjs.org/docs/app/building-your-application/caching#fetch-optionsnexttags-and-revalidatetag).

<a id="update-returns" />

### Returns

**update**

- `Promise`: Promise\<[AdminUserResponse](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminUserResponse)> — The user's details.
  - `user`: [AdminUser](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminUser) — The user's details.
    - `id`: `string` — The user's ID.
    - `email`: `string` — The user's email.
    - `first_name`: `null` | `string` — The user's first name.
    - `last_name`: `null` | `string` — The user's last name.
    - `avatar_url`: `null` | `string` — The URL of the user's avatar image.
    - `metadata`: `null` | `Record<string, unknown>` — Custom key-value pairs that can be added to the user.
    - `created_at`: `string` — The date the user was created.
    - `updated_at`: `string` — The date the user was updated.
    - `deleted_at`: `null` | `string` — The date the user was deleted.

## list

This method retrieves a list of users. It sends a request to the
[List Users](/api/admin/users/list-users)
API route.

### Example

To retrieve the list of users:

```ts
sdk.admin.user.list()
.then(({ users, count, limit, offset }) => {
  console.log(users)
})
```

To configure the pagination, pass the `limit` and `offset` query parameters.

For example, to retrieve only 10 items and skip 10 items:

```ts
sdk.admin.user.list({
  limit: 10,
  offset: 10
})
.then(({ users, count, limit, offset }) => {
  console.log(users)
})
```

Using the `fields` query parameter, you can specify the fields and relations to retrieve
in each user:

```ts
sdk.admin.user.list({
  fields: "id,email"
})
.then(({ users, count, limit, offset }) => {
  console.log(users)
})
```

Learn more about the `fields` property in the [API reference](/api/admin/select-fields-and-relations).

## generateResetPasswordToken

This method generates a reset password token for a user. It sends a request to the
Generate Reset Password Token for a User API route.

Useful for constructing the reset password link without sending an email.

The token is short-lived, can only be used once, and generating it invalidates
any reset password token previously issued for the user.

> **Note**
>
> This is available starting from [Medusa v2.20.0](https://github.com/medusajs/medusa/releases/tag/v2.20.0).

### Example

```ts
sdk.admin.user.generateResetPasswordToken("user_123")
.then(({ token }) => {
  console.log(token)
})
```

<a id="generateresetpasswordtoken-parameters" />

### Parameters

**generateResetPasswordToken**

- `id`: `string` — The ID of the user to generate the token for.
- `headers`: [ClientHeaders](/resources/references/js_sdk/admin/types/js_sdkadminClientHeaders) (optional) — Headers to pass in the request.
  - `tags`: `string`\[] — Tags to cache data under for Next.js applications. Learn more in [Next.js's documentation](https://nextjs.org/docs/app/building-your-application/caching#fetch-optionsnexttags-and-revalidatetag).

<a id="generateresetpasswordtoken-returns" />

### Returns

**generateResetPasswordToken**

- `Promise`: Promise\<[AdminUserResetPasswordTokenResponse](/resources/references/types/HttpTypes/interfaces/typesHttpTypesAdminUserResetPasswordTokenResponse)> — The generated reset password token.
  - `token`: `string` — The generated reset password token. Append it to the admin's `/reset-password` page as a `token` query parameter to build a link the user can open to set a new password. The token is short-lived, can only be used once, and generating it invalidates any reset password token previously issued for the user.
